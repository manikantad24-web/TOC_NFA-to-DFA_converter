# Algorithm Guide

This project visualizes three automata operations:

1. ε-closure
2. NFA → DFA subset construction
3. DFA minimization using iterative partition refinement

## 1. Finite automaton model

A finite automaton is represented as:

```text
(Q, Σ, δ, q0, F)
```

where:

- `Q` = set of states
- `Σ` = input alphabet
- `δ` = transition function
- `q0` = start state
- `F` = set of final states

## 2. ε-closure

The ε-closure of a state/set of states contains every state reachable using only ε-transitions, including the original states.

The implementation uses a stack and a visited set:

```text
closure = S
stack = S

while stack is not empty:
    remove a state s
    for each ε-transition s → t:
        if t is not already in closure:
            add t to closure
            push t onto stack
```

The visited/closure set also prevents infinite loops when ε-transitions contain cycles.

## 3. NFA → DFA subset construction

A DFA state represents a **set of NFA states**.

### Initial state

```text
DFA start = ε-closure({NFA start})
```

### Transition

For a DFA state `S` and input symbol `a`:

```text
move(S, a) = union of NFA transitions on a from every state in S

next = ε-closure(move(S, a))
```

If `next` has not been discovered, it becomes a new DFA state.

A DFA state is final when its represented NFA-state set contains at least one NFA final state.

The application continues until every reachable DFA state has been processed.

### Why the number of states can grow

An NFA with `n` states can theoretically produce up to:

```text
2^n
```

different DFA state subsets.

In practice, only reachable subsets are generated by this project.

## 4. DFA minimization

After conversion, the project minimizes the DFA using **iterative partition refinement**.

Initial partition:

```text
{final states}, {non-final states}
```

The algorithm repeatedly compares states in the same group.

Two states remain in the same group only when, for every input symbol, their transitions lead to states belonging to the same current partition.

The process stops when no group can be split further.

Each final partition becomes one state in the minimized DFA.

> Note: The implementation uses a straightforward iterative partition-refinement approach. It is not the optimized Hopcroft algorithm.

## 5. String simulation

For a DFA and input string `w`, simulation starts at the DFA start state and follows exactly one transition for each input character.

```text
current = start

for each character c in w:
    current = δ(current, c)

accept if current is final
```

If a transition is missing, the simulation enters a rejecting/dead condition.

The UI exposes each simulation step so that the state changes can be studied visually.

## 6. Complexity

### Subset construction

The number of reachable DFA states is at most `2^n`.

The exact running time depends on the number of reachable subsets, alphabet size, and ε-transition structure. A conservative implementation-level bound is exponential in `n`; the UI therefore reports `2^n` as the theoretical state bound.

### DFA minimization

This implementation uses straightforward partition refinement rather than Hopcroft's optimized algorithm. Its practical running time depends on the number of states, alphabet size, and number of refinement comparisons.

### String simulation

For an input string of length `m`:

```text
Time:  O(m)
```

because one DFA transition is processed per character.

## 7. Example

Suppose:

```text
States:   q0, q1, q2
Alphabet: a, b
Start:    q0
Final:    q2
```

and:

```text
δ(q0, a) = {q0, q1}
δ(q1, b) = {q2}
```

Then:

```text
D0 = {q0}
D1 = {q0, q1}
D2 = {q2}
```

with:

```text
D0 --a--> D1
D1 --b--> D2
```

Because `D2` contains the NFA final state `q2`, `D2` is a DFA final state.
